# 週案エディタ（School Plan Note）

**週案エディタ（School Plan Note）** は、小学校（および小中学校）の教員向けに開発された、週案（週間指導計画）および校務支援のWebアプリケーションです。

Google Apps Script (GAS) と Google スプレッドシートをバックエンドとして利用し、最新の生成AI（Gemini API）を組み込むことで、教員の日常的な事務作業の負担を大幅に軽減することを目的としています。

## 🖥 画面構成（8つのタブ）

アプリはシングルページ構成で、画面上部の8つのタブを切り替えて使います。以下の機能説明は、このタブ名で参照しています。

| タブ | 何をする画面か |
|---|---|
| **週案** | 週単位のグリッドに授業予定を入力する。起動時に開く画面 |
| **行事予定** | 学校の年間行事予定PDFを登録・閲覧する |
| **タスク** | 準備物・連絡事項などのタスクを管理する（未処理件数がタブにバッジ表示） |
| **単元** | 「単元マスタ」シートを表形式で編集する（画面見出しは「単元マスタ編集」） |
| **学級通信** | 学級通信をブロックエディタで作り、PDF出力・Classroom投稿する |
| **時数** | 教科別の実施時数集計と、年度末の過不足シミュレーション |
| **PDF読み込み** | 指導計画PDF・行事予定PDFをAIで解析して取り込む |
| **設定** | 使用中のデータベース、システム設定、固定時間割、標準時数、データ保全・復元など |

タブの右端には**表示テーマの切替ボタン**があり、押すたびに「自動（OSの設定に追従）→ ライト → ダーク」を巡回します。

## 🚀 主な機能 (Features)

### 1. デジタル週案（週間指導計画）

*   ブラウザ上の直感的なグリッドUIで、1週間分の予定を入力・管理できます。行は上から **行事／登校前／朝学習／1校時／2校時／中休み／3校時／4校時／昼休み／5校時／6校時／放課後／宿題／持ち物** の14行で、各校時は「教科」「単元」「学習活動」の3つに分かれています。土曜・日曜の列は表示/非表示を切り替えられます。

*   セルはダブルクリック（ダブルタップ）で編集でき、**ドラッグ＆ドロップでのコマ移動・Undo（元に戻す）**にも対応しています。朝学習・中休み・昼休み・放課後の欄には、「タスク」タブに登録したタスクをボタンから転記できます。

*   **セル操作は閲覧モード・編集モードのどちらでも同じ**: コマ（教科・単元・学習内容のひとかたまり）のコピー＆ペースト、クリア、入れ替え、元に戻すは、モードを行き来しなくてもそのまま使えます。
    *   `Ctrl+C` / `Ctrl+V`: 閲覧モードと同じキーがそのまま使えます。編集モードでは、**文字を選択していない時**の `Ctrl+C` がコマ全体のコピーになり、コピーしたコマを `Ctrl+V` するとセルごと貼り付きます。文字を選択してのコピーや、他アプリからコピーした文字の貼り付けは今までどおり文字として扱われるため、入力の邪魔になりません。
    *   **右クリック**（コピー / ペースト / クリア / 元に戻す）も両モードで開きます。編集モードで文字を選択している時だけは、ブラウザ標準のメニューを優先します。
    *   タブレットなど右クリックできない端末では、編集モードで**選択中のセルの右上に出る「⋮」**から同じメニューを開けます（出るのは選択中の1セルだけなので画面は散らかりません）。編集モードの長押しは文字選択のまま残しています。
    *   編集中の入力内容は、これらの操作や再描画をはさんでも失われず、カーソル位置も保たれます。「キャンセル」を押した時は、入力もセル操作もまとめて編集開始前の状態に戻ります。

*   **登校前タスク列**: 「行事」列と「朝学習」列の間に、出勤後・児童登校前に済ませておくタスクを記入できる「登校前」列を用意しています。既存のスプレッドシートに列が無い場合は、カスタムメニュー「週案ツール」>「その他」>「登校前タスク列を追加」で「行事」列の直後に自動追加できます（**コンテナバインド型のみ**）。印刷時は印刷オプションのチェックボックスで表示するかどうかを選べます（初期状態は非表示）。
    
*   **祝日の自動表示**: 内閣府が公開する祝日データ（`syukujitsu.csv`）を自動取得し、週案グリッドの該当日を赤色で強調して祝日名（例：「海の日」）をバッジ表示します。印刷時も標準・コンパクト両レイアウトで祝日の列を赤系で色分けし、祝日名を表示するため、休みの日が一目で分かります。祝日データは未取得なら週案の生成時に自動取得されます。コンテナバインド型では、スプレッドシートを開いた際に**前回取得から25日以上経っていれば自動更新**され、カスタムメニュー「週案ツール」＞「その他」＞「祝日データを更新」から手動更新もできます。

*   **入力支援メニュー**: ツールバーの「入力支援」に、**固定時間割反映／単元自動入力／以降を一括自動入力／単元をずらす**をまとめています。グリッドの右側には開閉できる「今週のタスク」サイドバーがあり、ツールバーのキーボードアイコンからショートカット一覧を確認できます。

*   **AI自動入力**: 「単元マスタ」の進捗と過去の履歴を照らし合わせ、次の時間の学習内容を自動で割り当てます。その週だけの自動入力と、その週以降をまとめて埋める一括自動入力を選べます。

*   **進捗つき単元選択**: 週案の単元選択モーダルに、単元ごとの指導状況（未指導／○時間目まで実施済み／指導済み）を表示します。指導が終わった単元は既定で折りたたまれて下に送られ、次に指導する単元が先頭に強調表示されるため、毎回一覧から目で探す必要がありません。単元名での検索もでき、単元を選んだあとの「何時間目」も自動で次の時間目が初期選択されます。

*   **週をまたいだ全文検索**: 週ナビゲーションの「検索」ボタンから、すべての週の入力内容（行事・朝学習・各校時の教科/単元/学習内容・宿題・持ち物・振り返りなど）をキーワードで横断検索できます。「あの実験いつやったっけ」も一発で見つかり、検索結果をクリックするとその週の週案へジャンプします。

*   **印刷**: 「印刷」ボタンで印刷オプションが開きます。レイアウトは**標準（A4・2ページ）／コンパクト（A4・1ページ）**の2種類。行事・登校前・朝学習・中休み・昼休み・放課後・教科時数表・週のまとめ・Todoリストの9項目を個別にON/OFFでき、フォントサイズも8〜14pxで調整できます（選択内容はブラウザに記憶されます）。Todoリストと教科時数表は標準レイアウトの2ページ目にのみ印刷されます。

*   **固定時間割の反映**: 「設定」タブの「固定時間割エディタ」で基本の時間割を登録しておくと、週案画面の「入力支援」からその週へ一括反映できます。「年間一括転記」を使えば、長期休業期間を除いた今後のすべての週へまとめて転記できます（既存の入力は上書きされます）。
    *   転記が書き込むのは、エディタに表示中の内容ではなく**保存済みの固定時間割**です。取り違えて「前の時間割が入った」とならないよう、転記の前に**実際に書き込まれる時間割を表で確認**できます。エディタに未保存の変更があるときは警告し、その場で保存してから転記できます。
    *   固定時間割が空のまま転記すると対象週の時程・朝学習・各校時が消えるため、実行前に警告します。
    

### 2. 生成AI (Gemini) による業務アシスト

*   **PDF自動読み取り**: 学校配布のPDF（年間指導計画・行事予定）をAIが解析し、スプレッドシートに転記します。「PDF読み込み」タブに**ドラッグ＆ドロップするか、クリックしてファイルを選ぶ**方式で（複数可・1ファイル15MBまで）、ファイルごとの処理状況が画面に表示されます。抽出結果は書き込み前にプレビュー（**行事予定は月ごと**、**指導計画は教科ごと**）で確認・修正・除外してから反映できます。指導計画の反映時は、同じ教科の既存データが置き換えられます。

*   **学級通信のAI生成**: 「学級通信」タブでは、その週の週案をもとに**通信全体をAIが一括生成**（見出し・あいさつ文・学習紹介・お知らせ・結び／文体も選択可）できるほか、テキストブロック単位での**本文生成・リライト**も行えます。

*   **タスク自動抽出**: 週案の予定（実験、特別な行事など）から、事前に準備すべきタスク（準備物、連絡事項など）をAIが自動で洗い出し、優先度付きでリストアップします。

*   **タスク進行管理**: タスクは「未着手→進行中→完了」の3段階で進行を管理でき、優先度（高・中・低）やメモも設定できます。期限切れ・今日が期日のタスクはナビゲーションのバッジや進行状況サマリーで一目で把握できます。**メールリマインダー**を有効にすると、指定した時刻（0〜23時・既定は7時）に「期限切れ／今日が期日／1週間以内」の未完了タスクが毎日メールで届きます（対象が0件の日は送信されません）。

*   **単元の時数再構成**: 「単元」タブの表で、各行の魔法のステッキのアイコン（`auto_fix_high`）から、「この単元を◯時間に組み直したい」をAIに任せられます。実際の進度に合わせて時数を増減させると、学習活動が新しい時間数に合わせて統合・分割されます。**週案に入力済みの時間は変更されません**（AIには渡されません）。結果は必ずプレビューで確認・修正してから反映され、単元マスタ上の並び順（＝年間指導計画の順）も保たれます。反映前の状態は復元ポイントとして保存されます。

*   **年間時数の再配分**: 「時数」タブの年度末シミュレーションで過不足のある教科に「調整案」ボタンが表示されます。標準時数に届くよう、未指導の単元へ時数を配分し直す案を作成します。まず機械的に比例配分した案を作り、AIはその調整だけを行うため、AIが使えない場合でも必ず案が出ます。
    

### 3. 単元マスタの編集と整合性チェック

「単元マスタ」シートは **1行 = 単元の1時間分** という持ち方で、総時間数を同じ単元の全行に重複して持ちます。そのため使い込むうちに「総時間数と実際の行数が合わない」「何時間目が重複・欠番になっている」といったズレが溜まりがちです。

*   「単元」タブでは、**教科名・単元名・総時数・時数・学習活動**の5列を表形式で直接編集できます。教科での絞り込みと単元名での検索、行の追加・削除にも対応しています。

*   「単元」タブの「整合性チェック」ボタンで、こうしたズレを一覧表示し、ワンクリックで修復できます（AIは使いません）。修復は**学習活動の内容を消しません**。並べ替え・連番の振り直し・総時数の再設定と、不足分の空行追加だけを行い、週案で既に指導済みの時数を下回らないように調整します。実行前の状態は復元ポイントとして保存されます。

*   あわせて、教科ごとの「単元時数の合計」と「年間標準時数」の比較も表示されます。両者が一致している必要はありませんが、年間指導計画を見直す目安になります。


### 4. 日次振り返り＆AI週報

*   **放課後の自動振り返りモード**: 放課後（15時以降）にアプリを開くと、その日の振り返りモードに自動で遷移。質問（予定との変更点・成果・課題・特記事項）に答えていくだけで、日報形式の振り返りが自動で完成し、データベースの「振り返り」列に記録されます。

*   **音声入力対応**: 振り返りの各入力欄には「音声入力」ボタンが付いており、話すだけで回答を記入できます（Chrome/Edge等の対応ブラウザ）。教室の片付けをしながらでも、その日の振り返りをさっと記録できます。
    
*   **あとで書く（保留）**: その場で対応できない場合は「あとで書く」を選択でき、保留された振り返りには「振り返り」ボタンの一覧から任意のタイミングで取り組めます。
    
*   **週報の自動生成**: その週の授業がある全ての日の振り返りが完了すると、AIが管理職報告用の「週のまとめ」を自動生成し、同一週の日曜日の振り返りセルに保存します。週案の印刷時には、フリースペース（時数表と検印欄の間）に掲載されます。
    

### 5. 時数管理

*   各教科の実施時数を自動集計。学年ごとの標準時数に対する消化割合や進捗をグラフで可視化します。

*   **年度末シミュレーション（過不足予測）**: 「今日までに実施済みの時数」と「明日以降に入力済みの予定時数」から年度末の着地見込みを教科別に計算し、標準時数に対する過不足を予測します。不足が見込まれる教科は警告表示され、「残り必要ペース（時間/週）」も表示されるため、年度途中での指導計画の調整に役立ちます。

*   **単元時数の再配分**: シミュレーションの表から、過不足のある教科の未指導単元へ時数を配分し直す案を作成できます（詳細は「生成AIによる業務アシスト」を参照）。
    

### 6. 学級通信（ニュースレター）エディタ

*   ブラウザ上で完結するブロックエディタを搭載。**見出し／テキスト／画像／段組み／ギャラリー／時間割／区切り線／QRコード／ワードアート**の9種類のブロックを挿入し、ドラッグ＆ドロップで並べ替えられます。

*   作成した通信は**PDF化して保存**できるほか、名前を付けて保存・読み込み・削除ができます。Google Classroom への投稿にも対応しています。

*   AIによる一括生成・本文生成・リライトが使えます（詳細は「2. 生成AI (Gemini) による業務アシスト」を参照）。


### 7. Google Classroom 連携

*   **明日の予定の自動投稿**: 「設定」タブで投稿時刻（0〜23時）を指定すると、毎日その時刻に翌日の時間割・宿題・持ち物をClassroomのストリームへ自動投稿します。時刻を空欄にすると自動投稿は解除されます。

*   「設定」タブの「明日の予定を投稿」「学級通信シートを投稿」ボタン、およびスプレッドシートのカスタムメニュー「週案ツール」＞「クラスルーム連携」（コンテナバインド型のみ）から、手動投稿もできます。


### 8. 複数学級モード（専科教員・複数学級担当向け）

*   設定タブでONにすると、学級ごとに専用のデータベースシートを持ち、画面左上の切替メニューで学級を切り替えて週案を管理できます。専科教員や複数学級を受け持つ場合に便利です。
    
*   **学級ごとに独立**するのは、データベースシート（週案・振り返り）・時数集計・担当学年・教科別標準時数です。**全学級で共通**なのは、タスク・単元マスタ・学級通信・固定時間割・長期休業設定・Classroom連携設定です。
    
*   学級を追加すると、既定の「データベース」シートをコピーした専用シート（年間カレンダー付き・入力内容は空）が自動作成されます。モードをOFFに戻しても学級シートとデータは削除されず、既定のシートを使う従来どおりの動作に戻ります。**使わない人の画面には一切表示されない**オプトイン方式です。
    

### 9. 年間行事予定PDFの閲覧（行事予定タブ）

*   学校ごとに作成された年間行事予定のPDFファイルを、アプリ内の「行事予定」タブでそのまま表示・閲覧できます。表示は先生自身のブラウザセッションでDriveプレビューを埋め込む形で行われます。

*   「PDFを追加」ボタンで **Google ピッカー**が開き、Drive上のPDFを複数選べます。選んだあとに任意で**学校名（グループ名）**を入力でき、一覧はその学校名ごとにグループ表示されます（学校名なしは「共通・学校未指定」として先頭に並びます）。ファイル名・学校名での絞り込み検索もできます。

*   **Driveにコピーもフォルダも作りません。** `drive.file` スコープで動かすため、保存されるのは選んだファイルの参照（ファイルID・ファイル名・学校名）だけです。したがって「一覧から外す」を実行しても、Drive上のPDF本体は削除されません。

### 10. データ保全・復元

「設定」タブの「データ保全・復元」から、記録を失わないための仕組みをまとめて利用できます。**追加のOAuthスコープは要求せず**、`drive.file` の範囲だけで動作します。既存シートの列順も変更しません。

*   **完全バックアップ**: スプレッドシート全体を別ファイルとして複製します。**1日1回の自動バックアップが既定で有効**（設定でOFFにできます）で、「今すぐ完全バックアップ」から手動作成もできます。保持は**30日／最大4世代**で、超えた分は作成・一覧表示のたびにドライブのごみ箱へ移動します。データベースの全消去や学級削除の直前には、自動バックアップの設定に関わらずバックアップが作られます。

*   **復元ポイント（スナップショット）**: 週案の保存前や、単元マスタの整合性チェック・時数再構成・年間再配分の反映前に自動で作られます。「今週の復元ポイント」から手動作成もでき、一覧から現在の内容との差分を確認したうえで書き戻せます。保持は**90日／最大300件**（自動作成は対象ごとに直近10件）です。

*   **ごみ箱（30日）**: タスク・週案の行・学級通信の削除は、いきなり消さずにごみ箱へ移動します。30日以内なら設定画面から元に戻せます。

*   **監査ログ**: いつ・誰が・どの操作をしたかを記録し、画面から一覧できます。APIキーなどの機密情報はログにもバックアップ設定にも保存しません。

これらの管理用データは、スプレッドシート内の `_週案_メタ` / `_週案_監査ログ` / `_週案_復元ポイント` / `_週案_ごみ箱` シートに保存されます。

## 🛠 技術スタック (Tech Stack)

*   **Backend**: Google Apps Script (GAS)
    
*   **Database**: Google Spreadsheet
    
*   **Frontend**: HTML5, CSS3, JavaScript (Vanilla JS / SPA Architecture)
    
*   **AI Integration**: Google Gemini API (`gemini-2.5-flash` 等)
    
*   **External API**: Google Classroom API（拡張サービス `Classroom` v1）／Google Drive REST API v3（`drive.file` スコープ。組み込みの `DriveApp` は `drive.file` で動かないため使いません。詳細は [`17_DriveApi.gs`](17_DriveApi.gs)）／Google Picker API（`apis.google.com` を読み込む唯一の外部スクリプト）／内閣府の祝日CSV

*   **OAuthスコープ**: `drive.file` / `script.scriptapp` / `script.external_request` / `script.send_mail` / `userinfo.email` / `classroom.courses.readonly` / `classroom.announcements`（`appsscript.json`）
    スプレッドシートも Drive も REST API を直接呼ぶことで `drive.file` だけで扱っています（`18_SheetsApi.gs` / `17_DriveApi.gs`。理由は [docs/B5](docs/B5_SHEETS_SCOPE_AUDIT.md)）
    
*   **同梱ライブラリ**: Bootstrap 5.3.3 / Bootstrap Icons 1.11.3 / SweetAlert2 11.14.5 /
    Material Symbols（使用アイコンのみのサブセット）を **CDNではなくリポジトリに焼き込んで**配信

### 外部CDNから実行コードを取らない

学校のネットワークは `cdn.jsdelivr.net` や `fonts.googleapis.com` を塞いでいることがある。
塞がれると、レイアウトが崩れ、確認ダイアログが `ReferenceError` で止まり、
アイコンが `calendar_month` のような英単語で表示される（実測）。
原因がアプリの外にあるため、先生が調べても分からない。

そのため、**無いと動かない／見た目が壊れるものは、すべてリポジトリに焼き込んでいる。**

| ファイル | 編集してよいか |
|---|---|
| `tools/build-vendor.mjs` / `tools/ms-ligatures.py` / `package.json` | **ここを直す**（原本） |
| `Vendor_Bootstrap.html` / `Vendor_Icons.html` / `Vendor_Sweetalert.html` | **手で編集しない**（生成物） |

原本を直したら、**必ず次を走らせてから push すること。**

```bash
npm install
npm run build:vendor   # Vendor_*.html を作り直す
npm run verify:icons   # アイコンが絵として描かれるか実ブラウザで確認
npm run quality        # 静的検査 + テスト（CI と同じ）
```

`npm run build:vendor` には Python の fonttools が要る（`pip install fonttools brotli`）。

本文用の Web フォント（Zen Maru Gothic ほか）だけは Google Fonts のまま。
これは届かなくても字の形が変わるだけで、端末側フォントを `--font-ui` の後ろに並べてある。

## ⚙️ セットアップと導入方法 (Setup & Installation)

このアプリケーションを使用するには、GoogleアカウントとGemini APIキーが必要です。

> ⚠️ **Gemini API キーは「課金を有効にした（有料ティアの）」ものを使ってください。**
> 無料ティアでは、送信した週案や PDF の内容が Google のモデル改善（機械学習）に使われる場合があります。
> 本アプリは Google ユーザーデータを AI の学習に使わせない方針（Limited Use）で運用しているため、
> 有料ティアのキーを前提としています。詳細は [プライバシーポリシー §4](docs/privacy-policy.html) を参照してください。

1.  **プロジェクトのクローン** 本リポジトリをクローンまたはダウンロードします。
    
2.  **Google スプレッドシートの準備** 新規でGoogleスプレッドシートを作成し、「拡張機能」>「Apps Script」を開きます。
    
3.  **ソースコードの配置** GASのエディタ（または `clasp` を使用）に、本リポジトリの `.gs` および `.html` ファイルをすべてコピーして保存します。

    > ⚠️ **更新するときは、増えたファイル・消えたファイルにも合わせてください。**
    > 既存ファイルだけ貼り替えると、新しく増えたファイル（例: `18_SheetsApi.gs`）が無いまま動き、
    > 「`sheetsOpenById_ is not defined`」のような原因の分かりにくいエラーになります。
    > 起動時に不足・残存を検出して名指しで知らせますが、`clasp push` を使うのがいちばん確実です。
`clasp` を使う場合は、必要なOAuthスコープ（メール送信 `script.send_mail` などを含む）を宣言した `appsscript.json` も一緒に反映してください。GASエディタで直接編集する場合は「プロジェクトの設定」で「`appsscript.json` マニフェスト ファイルをエディタで表示する」を有効にし、本リポジトリの `appsscript.json` の `oauthScopes` と `dependencies` を反映します。
    
4.  **Google サービスの有効化** GASエディタの「サービス」から **Google Classroom API**（`Classroom` / v1）を追加します。前の手順で `appsscript.json` の `dependencies` を反映していれば、この追加はすでに済んでいます。
    メール送信は組み込みサービス（`MailApp`）、スプレッドシートは Sheets REST API v4（`18_SheetsApi.gs`）、Drive は REST API v3（`17_DriveApi.gs`）の直接呼び出しで扱うため、Apps Script の「サービス」への追加は不要です。
    組み込みの `SpreadsheetApp` / `DriveApp` は使いません。使うと `spreadsheets` / `drive` という広いスコープを要求してしまうためです。

    > ⚠️ **ただし Cloud Console 側では、REST で呼ぶ API を有効にする必要があります。**
    > **Google Sheets API** と **Google Drive API**、および **Google Picker API** をオンにしてください（[C1](docs/C1_GCP_PROJECT_SETUP.md) ステップ2）。
    > オンにし忘れると「`Sheets API (403): ... has not been used in project ... or it is disabled`」で止まります。
    
5.  **Webアプリとしてデプロイ** 「デプロイ」>「新しいデプロイ」を選択し、種類を「ウェブアプリ」にしてデプロイします。発行されたURLにアクセスしてアプリを起動します。
    
6.  **アプリ内で初期設定** 初回起動時に**初期設定ウィザード**が開くので、案内に沿って設定します。**Gemini APIキーもここで入力**します。
    **スクリプトプロパティにAPIキーを登録する必要はありません。** 個人ごとの設定（Gemini APIキー・モデル、担当学年、教科別標準時数、固定時間割、Classroom連携、タスクリマインダー、複数学級設定など）は、アプリが `UserProperties` にユーザー別で保存します（キーは `sp_geminiApiKey` など。詳細は後述の「設定の保存先」）。
    

> **Note**
> スプレッドシートにバインドして使う場合、`SPREADSHEET_ID` スクリプトプロパティは `onOpen` / `doGet` の実行時に自動保存されるため、手動設定は不要です。配布元がスクリプトプロパティに手で設定するのは、マルチテナント配布時の `sp_dbTemplateId`（DBテンプレートID）だけです。


> **⚠️ タスクリマインダー（メール通知）を使う場合の再承認について**
> メール送信機能（`MailApp`）を後から追加・更新した場合、既存の承認にはメール送信権限が含まれず、時間ベースのトリガーが「権限不足」で失敗します。上記の `appsscript.json`（`script.send_mail` / `userinfo.email` スコープを含む）を反映したうえで、**アプリを一度開き直して表示される権限リクエストを承認**してください。承認後にWebアプリの「タスク」画面からリマインダーを設定し直すと、正しい権限でトリガーが再作成されます。

> **⚠️ Drive スコープを `drive.file` に最小化しました（再承認が必要）**
> アクセス権を Drive フル（`auth/drive`）から **`auth/drive.file`**（アプリが作成・ユーザーが選択したファイルのみ）へ縮小しました。マニフェスト反映後は**再認可（同意し直し）が必要**です。これに伴う運用変更:
> - **「PDF読み込み」タブ（指導計画PDF・行事予定PDF）は、Driveフォルダの一覧取得をやめ、端末からの直接アップロード（ドラッグ＆ドロップ／クリックして選択）に統一**しました。
> - **「行事予定」タブのPDF一覧**は、Driveフォルダを読むのではなく、**Googleピッカーで選んだファイルの参照（ID・ファイル名・学校名）だけを保存**する方式です。アプリはフォルダを作らず、PDFのコピーも作りません。学校名はグループ名として使われるだけで、Drive上のフォルダ構成とは無関係です。
> - 「設定」タブから**「PDF格納フォルダID」の入力欄は削除済み**です（`drive.file` では任意フォルダにアクセスできません）。
> - 週案・学級通信のPDF出力／Classroom 投稿／バックアップは、アプリが作成するファイルのみを扱うため引き続き動作します。
> - 移行前にフル `drive` スコープで扱っていた既存ファイルは、`drive.file` 移行後に再認識されない場合があります（行事予定PDFは「PDFを追加」から選び直してください）。詳細は [`docs/B1_DRIVE_SCOPE_AUDIT.md`](docs/B1_DRIVE_SCOPE_AUDIT.md)。

*(※ 詳細なスプレッドシートのシート構成（データベース、単元マスタ、タスク等）は [`docs/DATABASE_SCHEMA.md`](docs/DATABASE_SCHEMA.md) を参照してください。新規作成機能（`createMyDatabase`）はテンプレートが無くても必要シートを自動構築します。)*

## 🏫 複数ユーザーへの配布（マルチテナント・実験的）

1つのWebアプリを共通URLで配布し、**利用者がGoogleログインすると各自のスプレッドシート（DB）に紐付く／新規作成できる**構成に対応しています（`11_Tenant.gs`）。学校をまたいで「誰でも共通URLからすぐ使い始める」運用を想定した仕組みです。

### 配布元の設定手順

1. **スタンドアロンのWebアプリとしてデプロイ**（スプレッドシートにバインドせず、単体のGASプロジェクトとして）。「デプロイ」>「新しいデプロイ」で以下を選びます。
    * **次のユーザーとして実行**：**ウェブアプリケーションにアクセスしているユーザー**
    * **アクセスできるユーザー**：配布範囲に応じて「全員（Googleアカウント）」または「同一ドメインの全員」

2. **DBテンプレートを用意**（任意）。テンプレートを設定しなくても、利用者の「新規作成」はアプリが必要シート（`データベース`・`単元マスタ`・`タスク`）を自動構築するため動作します（`initializeNewDatabase_`）。独自の書式・数式・サンプル単元などを含む「検証済みテンプレート」を配りたい場合のみ、完成済みスプレッドシートを**「リンクを知っている全員が閲覧可（＝複製可）」**に共有し、そのIDをGASの「プロジェクトの設定」>「スクリプト プロパティ」に登録します（設定時はテンプレート複製が優先されます）。詳細は [`docs/DATABASE_SCHEMA.md`](docs/DATABASE_SCHEMA.md)。
    * `sp_dbTemplateId`: テンプレートのスプレッドシートID

3. 利用者は共通URLを開くだけです。初回ログイン時に**オンボーディング画面**が表示され、
    * **新しく作成する**… 利用者自身のDriveにDBを作成して開始（`sp_dbTemplateId` が設定されていればそれを複製し、未設定なら必要シートをプログラムで構築します。**テンプレート未設定でも常に選べます**）
    * **既存のシートを紐付け**… 手持ちのスプレッドシートのURL/IDを入力して開始

    のいずれかを選ぶと、以降はその利用者専用のDBが自動で使われます（紐付け先は利用者ごとの `UserProperties` に保存）。

> **後方互換**: 従来どおりスプレッドシートにバインドして使う場合、この画面は表示されず動作は変わりません（バインド先が自動で紐付け済みとして扱われます）。

### 設定の保存先（個人設定 / 共有設定）

マルチテナントで正しく分離できるよう、**個人ごとに変わる設定はユーザー別（`UserProperties`）に保存**します（Gemini APIキー・モデル、担当学年、教科別標準時数、固定時間割、Classroom連携、タスクリマインダー、複数学級設定、行事予定PDFの参照リスト、初期設定ウィザード完了フラグ 等）。読み取りは「ユーザー別 → 従来のスクリプトプロパティ」の順にフォールバックするため、既存のバインド環境から移行しても設定は失われず、保存し直すと自動的にユーザー別へ移ります（`11_Tenant.gs` の `tGetProp_/tSetProp_`）。

- **共有のまま**: 祝日データ（全国共通）、DBテンプレートID（`sp_dbTemplateId`）など。
- **配布元の注意**: standalone プロジェクトの「スクリプト プロパティ」には個人設定を残さないでください（`sp_dbTemplateId` など共有設定のみ）。全ユーザーへ既定値として見えてしまうためです。
- **PDF一括読み込みのバッチ処理状態もユーザー別（`UserProperties`）**に保存されるため、複数ユーザーが同時にPDF読み込みを実行しても競合しません。バッチ処理はアクセスユーザーとして実行される時間主導トリガーで進むため、状態も同じユーザーの `UserProperties` で整合します。

## 📱 PWA対応（Chromeからアプリとしてインストール）

本アプリはPWA（Progressive Web App）としてインストールできます。ChromeやEdgeのアドレスバーから「アプリをインストール」を選ぶと、独立したウィンドウで動作するデスクトップアプリのように使えます。

> **仕組み**: GASのWebアプリURL（`script.google.com`）はGoogleのラッパーページ経由で配信されるため、そのままではPWAの条件（manifest等）を満たせません。そこで `docs/` フォルダのPWAシェル（manifest + Service Worker）をGitHub Pagesで公開し、その中にGASアプリを全画面のiframeとして埋め込む構成になっています。

### セットアップ手順

1. **GitHub Pages を有効化する**
    本リポジトリ（またはフォーク）の「Settings」>「Pages」を開き、Source を「Deploy from a branch」、Branch を `main` / フォルダを `/docs` に設定して保存します。数分後に `https://<ユーザー名>.github.io/SchoolPlan_Editor/` が公開されます。

    本家は独自ドメイン **<https://schoolplan-editor.giga-school.com/>** で配信しています（`docs/CNAME` がその設定です）。`docs/manifest.webmanifest` の `start_url` / `scope` / `id` は相対パス `./` にしてあるので、サブディレクトリ配信（`…github.io/SchoolPlan_Editor/`）とサブドメイン直下配信（`schoolplan-editor.giga-school.com/`）のどちらでもそのまま動きます。**絶対パスに書き換えないでください** — 配信場所が変わった瞬間に `scope` がページの URL を含まなくなり、PWA としてインストールできなくなります。フォークして使う場合は `docs/CNAME` を削除するか、自分のドメインに書き換えてください。

2. **GASアプリのURLを設定する**（どちらか一方でOK）
    *   **画面から設定**: 公開されたページを開くと初回にURL入力画面が表示されるので、GASの「デプロイ」で発行されたWebアプリURL（`https://script.google.com/macros/s/～/exec`）を貼り付けます。URLはそのブラウザのローカルストレージに保存されます。
    *   **ファイルで固定**: `docs/config.js` の `appUrl` にWebアプリURLを記載してコミットすると、全ユーザー共通の接続先として固定されます（学校内で配布する場合はこちらが便利です）。

3. **Chromeでインストールする**
    公開ページをChromeで開き、アドレスバー右端のインストールアイコン（画面のような形のアイコン）をクリックするか、メニュー「キャスト、保存、共有」>「ページをアプリとしてインストール」を選択します。画面左下の⚙メニューにも「アプリとしてインストール」ボタンが表示されます。

### 注意事項

*   GASアプリ側は、デプロイ時の「アクセスできるユーザー」設定に応じてGoogleアカウントへのログインが必要です。Googleのログイン画面はiframe内に表示できないため、**初回起動時は自動でログイン案内画面が表示されます**。「Googleでログインして始める」を押すと別タブでログイン・認可でき、このタブに戻ると自動で週案が表示されます（一度表示できた端末では次回以降この案内は出ません）。うまくいかないときは左下の⚙メニューから「新しいタブで開く（ログイン用）」で一度ログインしてから「再読み込み」してください。
*   Service Workerがキャッシュするのはシェル部分のみです。アプリ本体（GAS）はオンライン環境が必要です。
    圏外でシェルも本体も無い場合は `docs/offline.html`（外部資産にもJSにも頼らない画面）が表示されます。
*   iOS Safariでは「ホーム画面に追加」で同様にアイコンから起動できます（`beforeinstallprompt` が発火しないため、⚙メニューのボタンは「ホーム画面に追加（インストール）」として常時表示されます）。
*   **「ホーム画面に追加」は、かならずPWAシェル（入口ページ）で行う必要があります。** iOS Safariは*いま開いているページ*を登録し、しかも**必ず成功します**。`script.google.com` の `/exec` ページを追加すると、アイコンが付かず（タイトルの一文字だけ）、アドレスバーとGASの「Googleではなく他のユーザーが作成した」表示が残ったまま開きます。**これはGAS側では直せません** — `/exec` の外枠はGoogleが出しているページで、`apple-touch-icon` も manifest も差し込めない（`HtmlService` で触れるのは title・viewport・favicon のみ）ためです。そこでアプリ側は、シェルの外で開かれたことを検知したら（シェルからの `schoolPlanNote:shellAck` が届かない）、iOSに限り画面上部に入口ページへ戻る案内を出します。戻り先は `00_config.gs` の `PWA_SHELL_URL` で、フォーク時はここを自分のGitHub PagesのURLに書き換えてください（空文字にすると案内を出しません）。ログイン用に「新しいタブで開く」を押した先生がそのタブのまま追加してしまうのが、実際に起きた経路です。
*   **紹介ページ `docs/about.html` にも manifest とインストール導線を置いてあります。** ポータルやOAuth同意画面の「アプリのホームページ」からの入口は紹介ページなので、ここに manifest が無いと、iOS Safariの「ホーム画面に追加」が**アプリではなく紹介ページのブックマーク**（アイコンはページの縮小画像）を作ってしまいます。紹介ページの「ホーム画面に追加」は、いったんアプリの入口（`./?install=1`）へ渡し、そこで手順を出します — iOS Safariは*いま開いているページ*を登録するため、追加の操作は manifest と `apple-touch-icon` を持つ入口ページで行う必要があるからです。逆に紹介ページに `apple-mobile-web-app-capable` は**書きません**（manifestを読まない古いiOSで、紹介ページ自体が枠なしで開く行き止まりになります）。品質ゲートの `GIGA_LANDING_*` がこれらを見ています。
*   左下の⚙メニューは**PWAシェル（GitHub Pages）側のUI**で、アプリ本体が表示されている間だけ出ます。GASのWebアプリURLを直接開いた場合は表示されません。

### シェルを更新するときの手順

1. `docs/` の中身を変更する。
2. **`docs/sw.js` の `CACHE_NAME` の版を必ず上げる**（`schoolplan-editor-shell-v5` → `v6`）。
    上げ忘れると、直した内容が先生の端末に届かない。
3. 更新は**先生が「最新にする」を押すまで切り替わらない**設計にしてある。
    入力中に画面が入れ替わると、打ちかけの週案が消えるため。

> キャッシュの接頭辞 `schoolplan-editor-shell-` は**このリポジトリ専用**である。
> 独自ドメイン移行前は `gigayama.github.io` に複数アプリが同居していたため、
> 接頭辞を他リポジトリ（`school-plan-note-shell-`）と共有すると、
> 片方が有効になるたびにもう片方のキャッシュを消してしまっていた。
> 現在はアプリごとに専用サブドメイン（`schoolplan-editor.giga-school.com`）を持つが、
> 移行前の端末に残った旧オリジンの Service Worker のために接頭辞は残してある。

## 💡 使い方 (Usage)

1.  デプロイで発行された**WebアプリのURL**（`https://script.google.com/macros/s/～/exec`）を開きます。PWAとしてインストールしている場合はそのアイコンから起動します。

2.  初回起動時は、設定が不十分な場合に**初期設定ウィザード**が自動で開き、**担当学年 → Gemini APIキー → Google Classroom連携（任意）→ 年間カレンダー**の4ステップを案内します。最後にまとめて保存され、すべて後から「設定」タブで変更できます（「設定」タブの「初期設定ウィザード」ボタンからいつでも再実行できます）。

3.  「週案」タブで日々の授業予定を入力します。「AI自動入力」ボタンで単元を自動割り当て可能です。

4.  「タスク」タブを開くと、入力された週案を元にAIが準備物をサジェストします。

5.  放課後（15時以降）に開くと、その日の**振り返り**が自動で立ち上がります。

> ⚠️ **カスタムメニュー「週案ツール」は、コンテナバインド型で使う場合だけのものです。**
> `01_Main.gs` の `onOpen()` はスプレッドシートに紐付いたスクリプトでしか動かないため、
> [D1](docs/D1_STANDALONE_DEPLOY.md) のスタンドアロン配布（共通URL）で使う場合はメニューは出ません。
> Classroomへの手動投稿・シート保護・キャッシュのクリア・PDF処理の強制停止は Web アプリ側にも
> 同じ操作があります。**「登校前タスク列を追加」と「祝日データを更新」はメニュー専用**で、
> スタンドアロン運用では実行できません（祝日データ自体は、未取得なら週案生成時に自動取得されます）。
> スタンドアロン運用では `script.container.ui` スコープを要求しないため、
> バインド型でメニューを使いたい場合は `appsscript.json` に自分で追加してください。

## ✅ 品質ゲート (Quality Gate)

静的検査と回帰テストを `npm` スクリプトにまとめてあり、CI（`.github/workflows/quality.yml`）が Pull Request と `main` への push で **Node 20 / 22** の両方で同じものを実行します。

```bash
npm ci          # 依存の取得（CI は --ignore-scripts 付き）
npm run check   # 静的検査（quality.config.json の設定で実行）
npm test        # 回帰テスト（node --test / tests/）
npm run quality # 上の2つをまとめて実行
```

`npm run check` は、必須ファイルの存在、`App.html` から参照される `include()` の解決、禁止OAuthスコープ（`auth/drive` 全体・`https://mail.google.com/`）の混入、`postMessage` のワイルドカード送信先などを検査します。例外として許可する箇所は `quality.config.json` の `securityExceptions` に明示されています。
