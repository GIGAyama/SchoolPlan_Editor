# C4: Google の審査（verification）を申し込む

> **この手順でやること**：アプリを「確認済み」にしてもらうため、Google に審査を申し込みます。
> これが通ると、ログイン時の「確認されていないアプリ」警告が消え、だれでも安心して使えます。
> **かかる時間の目安**：申請の準備に30〜60分／**承認まで**：数日〜数週間（Google 側の対応による）
> **前提**：C1・C2・C3 が終わっていること

---

## はじめに：なぜ審査が必要？

Classroom への投稿など「重い機能（sensitive スコープ）」を使うアプリは、
公開前に Google の審査を受けます。審査に通るまでは、初めて使う先生の画面に
**「確認されていないアプリ」** という警告が出ます（テストユーザーは回避可能）。

審査を通せば、この警告が消えます。

> 💡 **朗報**：このアプリは Drive を `drive.file`（ファイル単位）に絞っているので、
> いちばん厳しい審査（restricted スコープ向けの CASA セキュリティ評価）を**避けやすい**作りです。

---

## 申請前の準備チェックリスト

審査をスムーズに進めるため、先に次をそろえます。

### 1. 同意画面まわり（C2・C3 の再確認）
- [ ] アプリ名・サポートメールが正しい
- [ ] プライバシーポリシー／利用規約ページが公開されていて、内容が実際の動きと合っている
- [ ] `{{ }}` プレースホルダが残っていない
- [ ] 承認済みドメインに `giga-school.com` が入っている（サブドメインは自動で含まれます）
- [ ] ホームページ欄が `about.html`（紹介ページ）になっている
      - `https://github.com/...`（リポジトリ）は所有権を確認できないため不可
      - `https://schoolplan-editor.giga-school.com/`（アプリ本体）はログイン画面になるため不可
- [ ] ホームページの所有権を Google Search Console で確認済み（下記）

### 1-2. サイトの所有権を確認する（Search Console）

審査では「そのサイトは本当にあなたのものか」を確認されます。未確認だと
**「ウェブサイトが登録されていません」** で差し戻されます。

独自ドメイン `giga-school.com` を持っているので、**「ドメイン」プロパティ**での確認を勧めます。
一度で `giga-school.com` 配下のサブドメイン全部（＝全アプリ）が確認済みになり、
アプリを増やすたびに確認し直す手間がなくなります。

1. [Google Search Console](https://search.google.com/search-console) を開きます。
2. **「ドメイン」** を選び、`giga-school.com` を入力します。
3. 表示された **TXT レコード**を、ドメインを買った事業者の DNS 設定に追加します。
4. 反映（数分〜1時間ほど）を待ってから「確認」を押します。
5. **Google Cloud と Search Console は同じ Google アカウントで操作**してください。別アカウントだと確認済みと見なされません。

<details>
<summary>DNS を触りたくない場合（URL プレフィックスでの確認）</summary>

1. **「URL プレフィックス」** を選び、`https://schoolplan-editor.giga-school.com/` を入力します。
2. 確認方法で **「HTML ファイル」** を選び、指示されたファイル（`googleXXXX.html`）をダウンロードします。
3. そのファイルを **`docs/` フォルダに置いて** `main` へコミット・プッシュします。
4. GitHub Pages の再公開（数分）を待ってから、Search Console で「確認」を押します。

この方法だとアプリ（サブドメイン）ごとに確認が必要になります。
なお `docs/google1e4241bb058bcc28.html` は旧ドメイン（`gigayama.github.io`）用に置いた確認ファイルです。
新しいプロパティを作り直した場合は、新しく指示されたファイルに置き換えてください。

</details>

### 2. スコープの説明を用意
審査では「なぜその機能が必要か」を聞かれます。次の説明を準備しておきます。

| スコープ | 説明の例 |
|----------|----------|
| `drive.file` | 先生が選んだ／アプリが作ったPDF・出力ファイルだけを扱うため。Drive全体は見ません。 |
| `spreadsheets` | 各先生専用の週案データベース（本人所有）を読み書きするため。 |
| `classroom.courses.readonly` | 連携するクラスの一覧を取得するため。 |
| `classroom.announcements` | 先生が自分のクラスに予定や学級通信を投稿するため。 |
| `script.send_mail` | 先生が設定したタスクのリマインダーを本人宛に送るため。 |
| `userinfo.email` | ログインした先生を見分けて、データを各自に分けるため。 |

### 3. デモ動画を用意（sensitive スコープがある場合）
Classroom の機能を含むので、**操作のデモ動画**が求められます。

> 📹 **撮影台本を用意しています → [C5: OAuth 審査用 デモ動画の撮影台本](C5_DEMO_VIDEO_SCRIPT.md)**
> シーンごとの操作手順・英語字幕の文面・スコープとの対応表・提出前チェックリストがそろっています。

要点だけ先に挙げると：
- YouTube に**「限定公開（Unlisted）」**でアップし、そのURLを申請に貼ります（「非公開」は審査担当が視聴できず差し戻しになります）。
- 内容：ログイン → 同意画面 → 各機能（特に Classroom 投稿）を実際に操作するところ。
- **同意画面を映すときはアドレスバーごと映し、URL の `client_id` が読める**ようにします。
- 同意画面は **English 表示**に切り替え、動画には**英語字幕またはナレーション**を付けます。
- 同意画面に表示されるアプリ名と、動画内のアプリ名を一致させます。
- **要求する sensitive スコープ 6 個すべて**（`spreadsheets` / `drive.file` / `classroom.courses.readonly` / `classroom.announcements` / `script.send_mail` / `userinfo.email`）の実演が必要です。

## 申請の手順　〔約20分〕

1. Google Cloud の **「OAuth 同意画面」** を開きます。
2. 公開ステータスが「テスト」なら、**「アプリを公開」** で本番環境にします。
3. sensitive スコープがあると、**「確認のため審査を申請」** のような案内が出ます。指示に従って進みます。
4. 求められる情報を入力します。
   - スコープごとの用途説明（上の表を活用）
   - デモ動画のURL
   - プライバシーポリシーのURL
5. 申請を送信します。以降は Google からのメールを待ちます。

---

## 申請したあと

- Google から**追加の質問メール**が来ることがあります。放置すると審査が止まるので、**早めに返信**しましょう。
- 修正を求められたら、同意画面やポリシーを直して再提出します。
- 承認されると「確認されていないアプリ」警告が消えます。

> 📝 **運用メモ**：申請日・担当者・やり取りの記録を残しておくと、
> あとで再申請やスコープ追加のときに役立ちます。
