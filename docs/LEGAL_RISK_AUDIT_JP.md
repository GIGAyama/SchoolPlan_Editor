# 法令適合性の点検（日本法）：このまま開発・公開してよいかの棚卸し

- 実施日: 2026-08-19
- 対象: `main`（`3893d84`）時点の全ソースと配布物（`docs/` の公開ページを含む）
- 観点: 個人情報保護法、著作権法（第三者ライセンスを含む）、地方公務員法および学校の情報セキュリティ規程、文部科学省の生成AI利活用ガイドライン、特定電子メール法、消費者契約法
- 位置づけ: 開発者による自己点検であり、法律の専門家による助言ではありません。自治体への導入前には、設置者の情報担当部署の確認を受けてください。

## 結論（先に要点）

**「今すぐ開発そのものをやめるべき」ものは、ひとつもありません。** アプリの設計方針（データを利用者の
Google アカウント内だけに置き、運用者側にサーバーを持たない）は、この種のツールとして筋がよく、
OAuth スコープの絞り込みも実際に守られています。

一方で、**このままの実装で不特定多数の先生に公開してはいけない箇所が 3 つ**あります。いずれも
「児童生徒の情報が、意図しない相手に届く」経路です。3 つとも修正可能で、直せば公開できます。

| | 件名 | 判定 |
|---|---|---|
| A-1 | 学級通信の PDF／ドキュメントを無条件で「リンクを知っている全員が閲覧可」にしている | **公開前に必須修正** |
| A-2 | 第三者の QR コード生成サービス（国外）へ、開示のないまま送信している | **公開前に必須修正** |
| A-3 | AI が「今日の様子」を創作し、教員の確認なしに Classroom へ自動投稿している | ~~機能を今すぐ自動投稿から外す~~ → **対応済み** |
| B-1〜4 | プライバシーポリシーの記載が、実装より安全側に振れている（4 件） | 公開前に是正 |
| C-1〜3 | 利用者どうしのデータ分離が、設定ミスで崩れる余地がある（3 件） | 公開前に修正推奨 |
| D-1 | 同梱している第三者 OSS のライセンス表示が不足（著作権法上の条件不履行） | 公開前に修正 |
| D-2 | 生成AI へ投入する指導計画 PDF の著作権 | 注意書きの追加で足りる |
| E | 問題なしと確認できた点 | — |

## A. このままの実装で公開してはいけないもの

### A-1. 学級通信の PDF／ドキュメントが、作るたびに「リンクを知っている全員が閲覧可」になる

**どこ**

- `07_WebApp.gs:739` … `generateNewsletterPdf()` が PDF を作った直後に実行
- `07_WebApp.gs:774` … `postNewsletterToClassroomFromWeb()` が Google ドキュメントを作った直後に実行
- `17_DriveApi.gs:221` … `driveShareAnyoneWithLink_()` が `{ role: 'reader', type: 'anyone' }` を付与

**何が起きるか**

学級通信には、児童の氏名・顔写真・行事での様子が入るのが通常です。現在の実装では、
**Classroom へ投稿するときだけでなく、印刷用に PDF を作っただけでも**そのファイルが
インターネット上の誰でも開ける状態になります。しかも、

- 画面にも README にもプライバシーポリシーにも、公開リンクになる旨の説明がありません
- 公開範囲を戻す導線も、公開したファイルの一覧もありません
- 期限もなく、一度公開されたリンクは残り続けます
- `downloadUrl` として `https://drive.google.com/uc?export=download&id=…` を画面に返すため、
  このURLが転送・引用されると、そのまま第三者に届きます

プライバシーポリシー 1 章の「入力データは利用者本人の Google アカウント内にのみ保存されます」という
説明とも矛盾します。保存先は本人のドライブでも、**公開範囲は全世界**です。

**法的な位置づけ**

- 公立学校での利用なら、設置者（地方公共団体）は個人情報保護法第 5 章の規律を受け、
  保有個人情報の安全管理措置（同法 66 条）の対象です。私立なら個人情報取扱事業者として 23 条。
- 文部科学省「教育情報セキュリティポリシーに関するガイドライン」を踏まえた自治体の規程では、
  「リンクを知っている全員」形式の共有は原則として禁止または要許可とされているのが通例です。
- 教員個人には地方公務員法 34 条の守秘義務があり、意図せぬ公開でもこれに触れ得ます。
- 「リンクを知っている全員」設定による児童生徒情報の露出は、実際に自治体で複数の事故事例があります。

**判定：改善すれば公開できる。ただし改善前の公開は避けるべき。**

**直し方**

1. 印刷用 PDF（`generateNewsletterPdf`）では共有設定を一切変更しない。所有者本人が開ければ十分。
2. Classroom への添付は `type: 'anyone'` をやめ、コースの参加者に限定した共有に変える
   （どうしても広い共有が必要な場合でも `type: 'domain'` ＋ ドメイン限定にとどめる）。
3. それでも公開リンクが必要な場面を残すなら、実行前に「このファイルはリンクを知っている全員が
   閲覧できる状態になります」と明示して同意を取り、作成済み公開ファイルの一覧と公開解除の
   ボタンを設定画面に置く。

### A-2. 第三者の QR コード生成サービス（国外事業者）へ、開示のないまま送信している

**どこ**

- `App_Js_06_Newsletter.html:880` … 編集画面のプレビュー
- `App_Js_06_Newsletter.html:2452` … 出力する学級通信の本文に埋め込む `<img src>`

いずれも `https://api.qrserver.com/v1/create-qr-code/?…&data=<入力したURL>` を呼んでいます。
`api.qrserver.com`（goqr.me）は Google とは無関係のドイツの事業者です。

**何が起きるか**

先生が QR ブロックに入力した URL が、そのままこの事業者へ送信されます。学級通信の QR は、
保護者アンケートの Google フォーム、学級の写真フォルダ、限定公開の動画など、
**URL 自体が実質的な鍵になっているもの**を貼る用途がほとんどです。さらに生成された画像は
外部リンクのまま学級通信に埋め込まれるため、配布物を開くたびに読み手の環境からも
この事業者へアクセスが飛びます。

**なぜ重いか**

- プライバシーポリシー 4 章は「本アプリが連携する生成AI サービスは Google の Gemini API ただ 1 つ」
  「上記以外の外部サービスへ、利用者のデータを送信することはありません」と明記しています。
  **実装がポリシーに反しています。**
- `docs/C5_DEMO_VIDEO_SCRIPT.md` は Google の OAuth 審査向けに「送信先の全列挙」を掲げていますが、
  そこにもこの送信先が入っていません。審査上の申告漏れになります。
- URL に個人を識別できる情報が含まれる場合、外国にある第三者への提供（個人情報保護法 28 条）
  に該当し得ます。同条は原則として本人の同意と、移転先国の制度に関する情報提供を求めます。

**判定：改善すれば公開できる。**

**直し方**

QR の生成をブラウザ内で完結させるのが最善です（MIT ライセンスの QR 生成ライブラリを
`tools/build-vendor.mjs` の仕組みで同梱すれば、学校のフィルタリング対策という既存の方針とも揃います）。
外部サービスを使い続けるなら、最低限、ポリシーへの明記・画面での警告・利用者の同意が必要です。

### A-3. AI が「今日の様子」を創作し、教員が確認しないまま Classroom へ自動投稿している

> **対応済み。** 自動投稿からは「今日の様子」を外し、予定（時間割・宿題・持ち物）の転記だけにしました。
> `postScheduleToClassroom_core_` は AI を呼ばなくなり、教員が確認・修正したテキストを受け取って
> 載せるだけになっています（トリガーは引数を渡さないため、自動投稿には構造的に付きません）。
> 「今日の様子」は設定タブの「今日の様子をつけて投稿」から、下書きを確認・修正してから投稿します。
> プロンプトからは「実際に行われたという前提で」を削り、予定に無い出来事・児童の反応を
> 書かせない条件を足しました。`tests/classroom-post.test.mjs` が、自動投稿の経路から
> AI が呼ばれないことを実行して検査しています。

**どこ**

- `08_Gemini.gs:612` `generateTodaySituationText_()` のプロンプト:
  「**授業が実際に行われたという前提で**、子どもたちが頑張っていた様子や学びの様子を、
  温かく具体的に書いてください」
- `05_Classroom.gs:186` … 毎日の定時自動投稿の本文に、この生成結果を追記

**何が起きるか**

生成AI は、その日の**予定**しか渡されていません。にもかかわらず「実際に行われた前提で」
「子どもたちが頑張っていた様子」を書くよう指示されています。つまり、
**誰も見ていない児童の様子を創作した文章が、学校からの連絡として保護者・児童へ配信されます。**
定時トリガーによる自動投稿なので、

- 学級閉鎖・臨時休業・行事変更でその授業が実施されなかった日にも配信されます
- 教員が内容を目にするのは、保護者に届いたあとです

**法的・行政的な位置づけ**

- 文部科学省「初等中等教育段階における生成AIの利活用に関するガイドライン（Ver.2.0、2024年12月）」は、
  生成物をそのまま対外的に用いることを戒め、教師による確認を前提としています。
- 学校名義の対外発信に事実と異なる記述が載ることは、地方公務員法 33 条（信用失墜行為の禁止）
  の問題になり得ます。個々の児童に及ぶ記述であれば、名誉・信用の問題にもなります。
- 利用規約 4 条は「AI 解析した内容は、必ず利用者自身が確認してください」と定めていますが、
  **自動投稿は構造的に確認を挟めません。規約と実装が矛盾しています。**

**判定：この機能は、今の形のままにしておくべきではない。**
アプリ全体の開発を止める必要はありませんが、**「今日の様子」の生成を自動投稿の経路から
今すぐ切り離す**のが妥当です。

**直し方**

1. 定時自動投稿からは「今日の様子」を外し、予定（時間割・宿題・持ち物）の転記だけにする。
   予定は事実の転記なので、自動でも問題ありません。
2. 「今日の様子」は、教員が手動で押したときに**下書きとして提示**し、
   本人が読んで直してから投稿する導線に変える。
3. プロンプトの「実際に行われたという前提で」を削り、
   「予定として案内する文章」に性格を変えるか、教員が入力した振り返りを材料にする。

## B. プライバシーポリシーの記載が、実装より安全側に振れている

ポリシー自体はよく書けていますが、次の 4 点は実装が追いついていません。表示と実態の食い違いは、
利用者に誤った安全性の認識を与えるため、公開前に文言か実装のどちらかを合わせる必要があります。

### B-1. 「運用者へデータを送信する仕組みそのものが存在しません」は言い過ぎ

`appsscript.json` は `"exceptionLogging": "STACKDRIVER"` を指定しています。`docs/config.js` に
運用者のウェブアプリ URL が固定されている以上、多くの先生は運用者が所有する Apps Script
プロジェクトの上で実行します。このとき、**捕捉されなかった例外のメッセージとスタックトレースは、
スクリプトの所有者＝運用者が閲覧できる実行ログに残ります。** 同一 Workspace ドメインの
利用者であれば、実行者の識別情報も所有者側から見えます。

さらに `99_Utils.gs` の `writeToLog_()` は、ログシートへの書き込みに失敗した場合の代替として
`console.error()` にメッセージ本文をそのまま出力します。ここに週案の記述が乗る経路があります。

**判定：改善すれば公開できる。** ポリシー 1 章・7 章を「例外ログ（内容を含み得る）は、
スクリプト所有者の実行ログに記録されます」と正確に書き直したうえで、
`console.error` にはラベルだけを出し、本文を出さないようにしてください。

### B-2. ブラウザに学級通信の下書き（画像を含む）を保存していることが未開示

`App_Js_06_Newsletter.html:2050` 以降で、学級通信の全ブロック（画像の base64 を含む）を
`nw_autosave` として、テンプレートを `nw_templates` として `localStorage` に保存しています。

ポリシー 3 章は「端末内に保存する情報」として、接続先 URL・起動記録・iOS 案内の 3 件しか
挙げていません。職員室の共用端末では、次に同じブラウザを使う人が下書きを開ける状態です。

**判定：改善すれば公開できる。** 開示を追加し、画像はそもそも `localStorage` に入れない
（現在も容量超過時にだけ落とす作りなので、常に落とす方針でよい）、
「新規作成」以外にも下書きを消す導線を用意してください。

### B-3. 音声入力（Web Speech API）の外部送信が未開示

`App_Js_04_Reflection.html:82` の `webkitSpeechRecognition` は、Chrome では音声データを
Google の音声認識サーバーへ送って処理します。振り返りの発話には、児童の氏名や
評価に関する内容が含まれ得ます。ポリシーの外部送信先一覧に記載がありません。

**判定：改善すれば公開できる。** 外部送信先として明記し、機能の説明にも一言添えてください。

### B-4. 「有料ティア必須」「学習に使われることはありません」は保証できない

`App.html:842` 以降と `App_Js_13_SystemTools.html:311` で有料ティアを使うよう案内している点は
適切です。ただし**無料ティアのキーでも実際には動作します**（課金状態を検査していません）。
それにもかかわらずポリシー 4 章と 5 章は「送信内容がモデルの学習に使われることはありません」と
断定しています。

**判定：改善すれば公開できる。** 「有料ティアのキーを前提としています。無料ティアのキーを
設定した場合、送信内容が Google の製品改善に利用される可能性があります」と条件付きの
記述に改めてください。

## C. 利用者どうしのデータ分離が、設定ミスで崩れる余地

### C-1. ScriptProperties へのフォールバックが、共有デプロイでは合流経路になり得る

`11_Tenant.gs:121` の `resolveSpreadsheetId_()` は、利用者ごとの UserProperties に値が無いとき、
スクリプト全体で共有される ScriptProperties の `SPREADSHEET_ID` を読みます。
`06_Settings.gs` 経由の `getSetting()`（`11_Tenant.gs` の `tGetProp_()`）も同じ構造です。

現在のコードは `SPREADSHEET_ID` を書き込みませんが、運用者が同じプロジェクトを
コンテナバインドでも使うなどして値が残ると、**まだ自分の DB を作っていない先生全員が、
その 1 つのスプレッドシートに合流します。** 同じ経路で `sp_geminiApiKey` が残っていれば、
全員の週案と PDF が運用者の API キーで送信されます（費用も、送信元の帰属も運用者側になります）。
ポリシー 4 章の「API キーは利用者自身が設定し、運用者は取得も保持もしません」と食い違います。

**判定：改善すれば公開できる。** ウェブアプリとして動いているとき（コンテナバインドでないとき）は、
ScriptProperties へのフォールバックを行わないようにしてください。

### C-2. 「アクセスしているユーザーとして実行」が文書化だけで、実行時チェックがない

`README.md:338` と `docs/D1_STANDALONE_DEPLOY.md:54` で正しく警告していますが、
コード側の検知がありません。誤って「自分（オーナー）として実行」でデプロイすると、
**全教員が 1 つの DB を共有し、他学級の児童に関する記述が相互に見えます。**

**判定：改善すれば公開できる。** `Session.getEffectiveUser()` と `Session.getActiveUser()` が
一致しない場合に起動を止め、デプロイ設定の直し方を表示してください。

### C-3. 同名ファイルのごみ箱送り

`07_WebApp.gs:737` の `driveTrashByName_(fileName)` は、利用者のドライブから同じ名前の
ファイルを探してごみ箱へ送ります。`学級通信_YYYYMMDD.pdf` という一般的な名前なので、
本アプリが作ったものでない同名ファイルを巻き込む可能性があります。
法令というより事故の話ですが、消える対象が児童情報を含む成果物になり得ます。

**判定：改善が望ましい。** アプリが作成したファイルの ID を記録して、それだけを対象にしてください。

## D. 著作権とライセンス

### D-1. 同梱している第三者 OSS のライセンス表示が不足している

`tools/build-vendor.mjs` で各ライブラリをリポジトリへ焼き込む判断（学校のフィルタリング対策）は
妥当ですが、**焼き込みの過程でライセンス表示が落ちています。**

| ファイル | 中身 | ライセンス | 現状 |
|---|---|---|---|
| `Vendor_Sweetalert.html` | SweetAlert2 11.14.5 の CSS と JS 全量 | MIT | **著作権表示・許諾文がまったく無い** |
| `Vendor_Icons.html` | Material Symbols のサブセット | Apache-2.0 | CSS コメントに「Apache License 2.0 / Google」のみ。ライセンス全文なし、改変の明示なし |
| `Vendor_Icons.html` | Bootstrap Icons 8 個 | MIT | 「Bootstrap Icons（MIT」の一言のみ。著作権表示・許諾文なし |
| `Vendor_Bootstrap.html` | Bootstrap 5.3.3 の CSS | MIT | `/*! … Licensed under MIT */` のバナーが残っている（比較的良好） |

MIT ライセンスは「上記の著作権表示および本許諾表示を、ソフトウェアのすべての複製または
重要な部分に記載する」ことを条件としています。条件を満たさない複製・公衆送信は、
許諾の範囲外＝著作権侵害となり得ます。Apache-2.0 はさらに、ライセンス全文の同梱、
NOTICE の保持、および**改変した旨の明示**を求めます。本リポジトリは Material Symbols を
サブセット化し可変軸を固定している（＝改変している）ため、この明示が必要です。

**判定：公開前に直すべき。作業量は小さい。**

**直し方**

1. `THIRD_PARTY_NOTICES.md` を追加し、同梱している各パッケージの著作権表示とライセンス全文を載せる。
2. `tools/build-vendor.mjs` が `node_modules/<pkg>/LICENSE` を読み、生成物の先頭コメントへ
   そのまま焼き込むようにする（手作業だと次の更新でまた落ちます）。
3. Material Symbols については「使用アイコンのみのサブセットとし、FILL 軸を 0 に固定する改変を
   加えている」と併記する。

### D-2. 生成AI へ投入する「年間指導計画 PDF」の著作権

教科書会社の指導書・年間指導計画は著作物です。解析のために送信すること自体は、
著作権法 30 条の 4（情報解析等のための利用）でおおむね許容されると考えられます。
ただし、抽出した学習活動の**文言をそのまま単元マスタへ保存する**行為は複製に当たる余地があり、
それを学級通信へ転載したり Classroom へ投稿したりすると、35 条（授業の過程での複製等）の
範囲を外れる可能性があります。

**判定：開発を止めるような話ではない。注意書きで足りる。**
「PDF読み込み」タブと MANUAL に、対象は自校で作成・編集した資料を基本とすること、
出版社資料の文言をそのまま配布物へ転載しないことを書き添えてください。

## E. 点検して問題がなかった点

- **OAuth スコープは実際に最小限。** `appsscript.json` は `drive.file` にとどめ、`drive` 全体・

  要求していません。`tests/drive-scope.test.mjs` と `tests/oauth-verification.test.mjs` で
  継続的に検査されています。ポリシーの記述どおりです。
- **広告・アクセス解析・行動追跡は 0 件。** `docs/` を含め、解析タグもトラッキング Cookie も
  ありません。Cookie 同意や電気通信事業法 27 条の 12（外部送信規律）の論点は、
  実質的に生じません（そもそも本アプリの提供者は電気通信事業者に当たりません）。
- **リマインダーメールの宛先は本人だけ。** `07_WebApp.gs:1840` は
  `Session.getEffectiveUser().getEmail()` を宛先にしています。第三者へ広告や勧誘を送る仕組みは
  無いため、特定電子メール法の同意取得・表示義務の対象になりません。
- **免責条項は消費者契約法を意識できている。** 利用規約 10 条 4 項に、
  強行法規により免責が認められない場合の救済条項があります。全部免責のまま無効になる、
  という典型的な失敗を避けています。13 条の管轄合意も、無償ツールとして過度ではありません。
- **リポジトリ内の画像に実在の個人情報は無い。** `docs/note/images/` の 23 枚を確認しました。
  すべてデモデータで、実在する児童の氏名・顔写真は写っていません。
- **履歴に API キーの混入は無い。** 全リビジョンを走査し、Google API キー形式の文字列は 0 件でした。
- **出力のエスケープは行われている。** 画面へ差し込む利用者入力は `escHtml` / `escHtmlAttr` を

- **ログの保存先は利用者自身のシート。** `99_Utils.gs` の `writeToLog_()` は利用者のスプレッドシート内の
