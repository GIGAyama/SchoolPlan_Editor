# note 入稿用の一式

連載「教室で使えるかもしれないもの作り」に載せる、週案エディタの紹介記事です。

```
docs/note/
├── schoolplan-editor-note-article.md   記事本文。そのまま note に貼れる形
├── images/                             画面のスクリーンショット 23点
└── README.md                           このファイル
```

## 今回の書き直しについて

作った理由を書き手から聞き取り、その筋で記事を組み直しました。前の版は「日曜の夜に週案を書いていると一時間が過ぎる」という一般的な場面から始まっていて、このアプリが生まれた本当のきっかけが入っていませんでした。書き直したのは次の箇所です。

- タイトル行。「週案がまだ書けていない」から、「週案は紙のほうが早い」と感じている先生に向けた題へ
- 🏫 はじめに。全面的に書き直し。スプレッドシート版の週案簿を配っていたこと、越えられなかった印刷の一点、だからアプリにした、という順に
- 📱 このアプリでできること。印刷のくだりを書き直し。文字の大きさのつまみ、土曜の列、ページごとの自動縮小を追加
- ✨ 導入のメリット。一つ目を「提出する紙の形を自分で決められる」に差しかえ、二つ目と三つ目も書き直し
- 🛠️ 【管理者向け】導入手順。子どもの情報を入れる欄をあえて作らなかった話を追加。箇条書き2か所を文章に、専門用語3語を言いかえ
- 📝 まとめ。スプレッドシートのほうが良かったところを正直に書く段落を追加
- 🏷 ハッシュタグ。前の版に無かったので新設

画面のスクリーンショットは撮り直していません。前回の23点をそのまま使っています。アプリ側の最後の更新と撮影日の差は10日で、lint の警告が出る30日には届いていません。

## 貼るまえに直すところ

- タイトル行の `#◯` が連載番号のままです。ここだけ実際の番号に直してください。推測で埋めていません。
- 記事に出てくるURLは `https://schoolplan-editor.giga-school.com/` です。GitHub Pages を有効にしていない場合は、GASのウェブアプリURLに差しかえてください。
- 🏫 はじめに に置いた前作の記事のURL `https://note.com/cute_borage86/n/n73dacf220e3f` は、書き手からうかがったものをそのまま置いています。この作業環境から note へ接続できないため、中身の確認はしていません。スプレッドシート版の週案簿を配っている記事で合っているか、貼る前に一度開いて確かめてください。

## すでに note に公開している場合

`giga-school.com/apps/schoolplan-editor/` は毎朝コミットから組み直されるので、この書き直しは翌朝に自動で反映されます。いっぽう note は手で貼ったまま止まります。すでに公開済みなら、タイトルと本文を貼り直さないと、note とサイトで中身がずれたままになります。貼り直しの手間に見合わないと判断される場合は、お知らせください。前の版に戻す形も取れます。

## note に貼る手順

1. note で新しい記事を作り、1行目のタイトル欄に `#◯` を直したタイトルを入れます。記事本文の1行目（`#` の行）は本文には貼りません。
2. `## 🏫 はじめに` から最後までを本文にそのまま貼ります。note は `##` を見出しとして受け取り、目次を自動で作ります。
3. 画像は自動で入りません。本文中の `![...](images/xx-....png)` を目印にして、その位置に `images/` の画像を手でアップロードしてください。貼りおえたら `![...](...)` の行は消します。
4. 画像の下にある一行の説明は、note の画像キャプション欄へ移してください。本文に残したままでも読めますが、キャプションに入れたほうが収まりがよくなります。
5. ハッシュタグは記事の末尾に `## 🏷 ハッシュタグ` として入れてあります。note のハッシュタグ欄へ移してください。

## 取材メモ

書き手にうかがった内容です。記事に入れたもの、あえて入れなかったものの両方を残します。

**作ったきっかけ。** もともとスプレッドシートと Google Apps Script で自作の週案簿を使っていた。スプレッドシートにしたのは、公務パソコンでも自宅のパソコンでも教室に持ち込む Chromebook でも、同じシートを開いて編集や確認ができるから。そこが Excel や紙の週案簿より優れていると考えていた。使っていてほとんどストレスがなく、世の中にあるどの週案簿より使いやすいと自負していた。だから誰でも使えるように一般化したものを note で配っていた。勤務先の学校でもクラスルームで共有したところ、ひとり、またひとりと使ってくれる先生が出てきて、使いやすいと喜んでくれたのが嬉しかった。

**納得がいかなかった一点。** 管理職に提出するときの印刷。Excel はセルの大きさを決めてそこに文字を縮小表示できるが、スプレッドシートは手で文字サイズを変える以外に方法がなく、文字が多くなるとセルの高さが伸びて、1ページに印刷したときに縦に細長い印刷物になってしまった。土曜日に授業がある週、手書きで振り返りを書きたい週など、そのときどきのニーズに合わせてシートを調整したりレイアウトを変えたりすることも、自分の技術では難しかった。そこを解決したくて開発を始めた。

**いまもスプレッドシートのほうが良いと感じるところ。** 保存。スプレッドシートは特別な操作なしにセルに書いた内容が保存されるので、書いた内容が消えたり意図せず上書きされたりすることがなかった。いまのアプリは自動的にデータベースのスプレッドシートに保存されるわけではないので、保存するための作業が必要になっている。

**あえて作らなかったもの。** テストとして知り合いの先生に使ってもらったときに、子どもの情報を入力するページがあるとありがたい、という話があった。スプレッドシートが外に出ることはないとはいえ、児童の情報を1か所にまとめて記入するようなものは、あえて作らなかった。

**いちばん届けたい相手。** 書き手のご家族に、別の学校で ICT 主任をしている先生がいる。デジタルやタブレットには詳しいが、週案に関しては紙のほうが便利で使いやすいとずっと言っていて、デジタルの週案を使っていなかった。このアプリを使ってもらったところ、使いやすいと言ってくれた。そういう、デジタルの週案にまだ挑戦したことのない先生に届けたい。

この最後の話は、記事の本文には入れていません。連載の決まりで、実際に使われた結果を作者の実体験として書くことができないためです。かわりに、届けたい相手像として題と 🏫 はじめに と 📝 まとめ の向きに使いました。本文に入れたい場合は、書き手ご自身の言葉として一段落足すのがよいと思います。

## 記事を強くするために足せるところ

聞けていないぶんを、あとから一段落だけ差し替えられる形にしてあります。

- 📱 の印刷のくだり。実際に管理職へ提出したときの反応が一行あると、印刷の話に重みが出ます
- 📝 まとめ。保存の話のあとに、いつ直すつもりかが一言あると、読み手が待てるようになります

## スクリーンショットの撮りかた

このアプリは Google Apps Script のウェブアプリで、本物の画面を出すには Google アカウントと先生ご自身のスプレッドシートが要ります。記事のために本番のデータを映すわけにいかないので、撮影は次の方法で行いました。

1. `App.html` の `<?!= include('...') ?>` を実体に差しかえて、1枚のHTMLに結合する。
2. `google.script.run` の受け答えだけを、3年生のサンプルデータを返すものに差しかえる。
3. そのページを実ブラウザ（Chromium）で開き、実際にボタンを押して撮る。

画面のHTML、CSS、JavaScript はリポジトリのものをそのまま使っています。画像の合成や加工はしていません。映っているデータだけがサンプルです。

撮影に使った一式は `.tmp-shots/` に置いていましたが、納品時に削除しています。撮り直すときは、同じ手順を作り直すか、実際にデプロイした環境から撮ってください。1のところは `tools/demo-video/build-preview.mjs` が同じことをしているので、2のサンプルデータを返す部分だけを足せば作り直せます。実環境から撮る場合は、スプレッドシートIDやメールアドレスが映り込まないよう気をつけてください。

撮り直すときはファイル名を変えないでください。本文からの参照が切れます。`--out docs/note/images` に同じ名前で上書きすれば、記事は直さずに済みます。

## 文体について踏襲したもの

- 太字、斜体、表、`→` `／` `：` などの記号を本文で使っていません（この README は入稿用のメモなので表を使っています）。
- 箇条書きは手順のときだけにしています。それ以外は文章です。導入手順の節にあった箇条書き2か所も、今回文章に直しました。
- 「デプロイ」「リポジトリ」「API」といった言葉を、先生に伝わる言い方へ置きかえています。
- 絵文字は見出しだけに使っています。
- 教室での出来事を実体験としては書いていません。「こうなればいいと思って作った」「〜だと思います」までにとどめています。効果を言い切っている箇所はありません。
- 見出しは連載の基本形に、目玉の機能ぶんとして「🗓 手が止まるのは『単元』と『学習内容』のところ」と「📊 時数の不安を、年度末まで先回りする」の2本を足しています。追加できる見出しは2本までなので、作った理由の話は新しい節を立てず、🏫 はじめに と 📱 と 📝 まとめ に入れました。
- 本文の字数は約9,800字です。
